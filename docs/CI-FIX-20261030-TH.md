# แก้ GitHub Actions ของ HRVec-Andaman2 รุ่น 1.11 — 30 ตุลาคม 2569

## ปัญหาที่พบ

งาน GitHub run 41003554494 หยุดที่ Verify school permissions in isolated PostgreSQL หลังติดตั้ง PGlite สำเร็จ โดย tests/schools-db.mjs บรรทัด 66 ได้ false แทน true หลังเปลี่ยนสิทธิ์เจ้าหน้าที่และสร้างเซสชันทดสอบใหม่ทันที

ระบบตรวจว่า auth.sessions.created_at ต้องมากกว่า profiles.sessions_revoked_before แบบเคร่งครัด เวลาเท่ากันยังใช้สิทธิ์ไม่ได้ ตัวสร้างเซสชันทดสอบเดิมอาศัย clock_timestamp() สองครั้งต่อกันจึงอาจได้เวลาเท่ากันบนสภาพแวดล้อมที่ทำงานเร็ว จำลองกรณีเวลาเท่ากันแล้วได้ผล false แบบเดียวกับ Error ที่รายงาน

## การแก้ไข

เพิ่ม tests/helpers/auth-session.mjs ให้จับเวลาฐานข้อมูลครั้งเดียว และสร้างเซสชันเฉพาะเมื่อเวลานั้นมากกว่าจุดยกเลิกเซสชันแล้ว หากนาฬิกายังไม่ผ่านให้รอ 1 มิลลิวินาทีแล้วตรวจใหม่ มีเวลาจำกัด 2 วินาทีเพื่อหยุดพร้อมข้อความที่ชัดเจน

ชุดทดสอบฐานข้อมูลทั้งสี่ไฟล์ใช้ตัวช่วยเดียวกัน เพิ่ม 5 assertions ตรวจว่าเซสชันที่เวลาเท่ากันและเซสชันเก่ายังถูกปฏิเสธ ส่วนเซสชันใหม่ต้องมีเวลามากกว่าจุดยกเลิกจริงและใช้สิทธิ์ได้ ไม่กำหนดเวลาเซสชันในอนาคตล่วงหน้า

แก้เฉพาะชุดทดสอบและเอกสาร กฎ strict >, RLS, SQL ฐานข้อมูลจริง, Edge Functions, Apps Script และรหัสผ่านใช้ของเดิมต่อ ไม่มีการปิดหรือข้ามชุดทดสอบเพื่อให้ผ่าน

## ใช้โปรแกรมอะไรและทำอย่างไร

1. ดาวน์โหลด HRVec-Andaman2-v1.11-CI-Fix.zip คลิกขวาใน File Explorer → Extract All… → Extract
2. เปิด GitHub Desktop เลือก Repository hrvec-andaman2 → Repository → Show in Explorer
3. จากโฟลเดอร์ที่แตก ZIP คัดลอกโฟลเดอร์ tests และ docs ไปวางทับในโฟลเดอร์ Repository เดิม ซึ่งมี dist และ supabase อยู่ระดับเดียวกัน เลือก Replace the files in the destination เมื่อถาม
4. ตรวจว่ามีไฟล์ใหม่ tests/helpers/auth-session.mjs และไฟล์ทดสอบ schools-db.mjs, institute-db.mjs, v110-db.mjs, v111-db.mjs ใช้ import ตัวช่วยนี้ครบ
5. กลับ GitHub Desktop ตรวจแท็บ Changes ใส่ Summary ว่า Fix CI session timestamp boundary กด Commit to main แล้ว Push origin
6. เปิด Chrome / Edge ไปที่ Repository → Actions เปิดงานรอบใหม่ที่เกิดจาก Commit นี้ รอ Verify school permissions in isolated PostgreSQL และ Deploy ผ่านเป็นสีเขียว
7. งานเก่าที่ปุ่ม Re-run jobs ใช้ Commit เก่า ให้ตรวจงานใหม่ที่มีโค้ดแก้แล้ว หากยังไม่ผ่าน ให้เปิดขั้นตอนสีแดงและส่ง Error ใหม่พร้อมชื่อไฟล์และบรรทัด
8. เมื่อ Deploy สำเร็จ เปิด Settings → Pages → Visit site แล้วกด Ctrl + F5

อัปเดตชุดทดสอบผ่าน GitHub เท่านั้น การแก้ครั้งนี้ไม่ต้องรัน SQL หรือสร้าง admin ใหม่ใน Supabase และไม่ต้อง Deploy Apps Script ใหม่
