## 3. อัปเดตหน้าเว็บของโครงการ HR ที่ใช้อยู่

### 3.1 เตรียมไฟล์บน Windows

1. ดาวน์โหลด HRVec-Andaman2-v1.9-GitHub-Source.zip แล้วแตกไฟล์
2. เปิดโฟลเดอร์โครงการเดิมที่เชื่อมกับ GitHub ใน VS Code ผ่าน File → Open Folder
3. สำรองโฟลเดอร์โครงการเดิมก่อนแทนไฟล์ โดยเฉพาะไฟล์ .env และ .env.bootstrap ให้เก็บเฉพาะเครื่องผู้ติดตั้ง
4. คัดลอกไฟล์และโฟลเดอร์จาก ZIP รุ่น 1.9 ลงในโฟลเดอร์โครงการเดิม เมื่อ Windows ถามให้เลือก Replace the files in the destination
5. เก็บโฟลเดอร์ .git เดิมไว้เพื่อรักษาการเชื่อมต่อ GitHub ไม่ลบ .git และไม่สร้าง Repository ใหม่
6. เปิด View → Show → Hidden items ใน File Explorer เพื่อให้เห็น .github และ .gitignore
7. ตรวจว่ามีไฟล์ .github/workflows/pages.yml; ไฟล์นี้อยู่ในชุด Source และใช้เผยแพร่หน้าเว็บ

### 3.2 ตรวจการเชื่อมต่อหน้าเว็บ

เปิด dist/config.js ใน VS Code ต้องมีรูปแบบดังนี้ โดยใช้ Publishable key ของโครงการ HR:

```js
window.HR_CONFIG = {
  supabaseUrl: "https://oftlfxiywhtoftxluviv.supabase.co",
  supabaseAnonKey: "PUBLISHABLE_KEY_ของโครงการ_HR"
};
```

**ZIP ชื่อ GitHub-Source ที่ส่งให้ใส่ค่าจริงที่เป็นค่าสาธารณะของโครงการ HR ไว้ใน dist/config.js แล้ว** จึงไม่ต้องสร้าง Key ใหม่ หากใช้ไฟล์จากแหล่งอื่นให้คัดลอก deployment/config.production.js ไปแทน dist/config.js

หา Publishable key ได้ที่ Supabase → โครงการ HR → Settings → API Keys → Publishable key ชื่อ default ห้ามใช้ service_role หรือ Secret key ใน dist/config.js

หน้าเว็บที่ส่งมอบตั้งค่า dist/config.js เชื่อมโครงการ HR จริงแล้ว ZIP สำหรับอัปเดตเว้นไฟล์นี้ไว้เพื่อรักษาค่าการเชื่อมต่อเดิมของคุณ

### 3.3 ตรวจไฟล์ก่อนส่ง

ใน VS Code เลือก Terminal → New Terminal หากเปิดเป็น PowerShell ใช้คำสั่งที่ลงท้าย .cmd ตามตัวอย่าง หรือกดลูกศรข้างเครื่องหมาย + ในแถบ Terminal → Select Default Profile → Command Prompt แล้วเปิด Terminal ใหม่

```text
node --version
npm.cmd run check
npm.cmd test
```

ผลที่ควรได้: ตรวจไวยากรณ์ผ่าน และการทดสอบ 100 รายการผ่าน หากไม่รู้จัก node ให้ติดตั้ง Node.js รุ่น LTS จาก https://nodejs.org แล้วปิด–เปิด VS Code ใหม่

### 3.4 Commit และ Sync Changes

1. กดไอคอน Source Control ทางซ้ายของ VS Code หรือ Ctrl + Shift + G
2. ตรวจรายการ Changes ว่ามีไฟล์ app.js, api.js, structure.js, template.js และไฟล์ฐานข้อมูลรุ่น 1.9
3. ตรวจว่าไม่มี .env, .env.bootstrap, รหัสผ่าน, service_role key, ไฟล์ Excel ข้อมูลบุคลากรจริง หรือสำเนาสำรองข้อมูลจริงอยู่ใน Changes
4. กด + เพื่อ Stage เฉพาะไฟล์โค้ดและแม่แบบเปล่า
5. ใส่ข้อความ Commit เช่น Upgrade HRVec-Andaman2 to v1.9 แล้วกด Commit
6. กด Sync Changes หรือ Push เพื่อส่งไป GitHub หากมีคำขอเข้าสู่ระบบ ให้ใช้บัญชีเจ้าของ Repository เดิม
7. ถ้าโปรแกรมแจ้งว่ามีไฟล์แก้ไขทั้งสองฝั่ง ให้ตรวจ Merge Conflicts ก่อนกด Sync อีกครั้ง ไม่เลือกเขียนทับไฟล์ลับหรือข้อมูลจริงโดยไม่ตรวจ

### 3.5 รอ GitHub Actions และเปิดเว็บ

เปิด Chrome หรือ Edge ไปที่ https://github.com/HRVec-Adaman2/hrvec-andaman2

1. เลือก Settings → Pages → Build and deployment → Source = GitHub Actions
2. เปิดแท็บ Actions แล้วเลือก Deploy HRVec-Andaman2 to GitHub Pages
3. Workflow เริ่มอัตโนมัติหลัง Push ไป main หรือกด Run workflow → main → Run workflow
4. รอให้การทดสอบและ Deploy เป็นเครื่องหมายถูกสีเขียว
5. กลับ Settings → Pages → Visit site หรือเปิด https://hrvec-adaman2.github.io/hrvec-andaman2/
6. กด Ctrl + Shift + R เพื่อโหลดไฟล์รุ่นล่าสุด ต้องเห็นข้อความท้ายหน้า “รุ่น 1.9”
7. เลือกเข้าสู่ระบบจริง ใช้บัญชีและรหัสผ่านแอดมินปัจจุบัน ระบบนี้ไม่ได้รีเซ็ตรหัสเดิม
8. หลังเข้าสู่ระบบ เปิดข้อมูลบุคลากร → เพิ่มบุคลากร แล้วตรวจว่ามี “สถาบันการอาชีวศึกษาภาคใต้ 2” ในตัวเลือกหน่วยงาน

ชื่อบัญชี GitHub ใน URL นี้คือ HRVec-Adaman2 ส่วนชื่อ Repository คือ hrvec-andaman2 การสะกดต่างกัน ให้ใช้ URL ตามที่ระบุ

หากยังไม่เห็น Workflow ให้ตรวจว่า .github/workflows/pages.yml อยู่บน Branch main และ Repository ไม่ได้มีโฟลเดอร์ครอบโค้ดเพิ่มอีกชั้น

## 4. ตรวจฐานข้อมูลที่อัปเกรดให้แล้ว

ใช้ Chrome หรือ Edge เปิด https://supabase.com/dashboard/project/oftlfxiywhtoftxluviv แล้วเลือก SQL Editor → New query วางคำสั่งตรวจต่อไปนี้แล้วกด Run:

```sql
select public.hr_schema_version();
select id, name, unit_type, is_active
from public.schools
order by id;
select column_name
from information_schema.columns
where table_schema='public' and table_name='personnel'
  and column_name='address';
```

ผลที่ควรได้ตามลำดับ: 1.9.0; รายการ 8 หน่วยงาน; และคำสั่งสุดท้ายไม่พบแถว ในโครงการ HR นี้ส่วนกลางเป็นรหัส 8 แต่โค้ดไม่ล็อกรหัส 8 เพื่อรองรับโครงการอื่นที่ใช้เลขนี้ไปแล้ว แม่แบบที่ดาวน์โหลดจากระบบใช้รายการปัจจุบันเสมอ

หากติดตั้งให้โครงการอื่นที่เป็นรุ่น 1.8 ให้เปิดไฟล์ migration รุ่น 1.9 ใน VS Code คัดลอก SQL ทั้งไฟล์ไป SQL Editor ของโครงการเป้าหมายหลังสำรองข้อมูล แล้ว Run เพียงไฟล์นี้ ฐานข้อมูลที่มีข้อมูลแล้วห้ามรัน supabase/schema.sql ทับ

ถ้าพบข้อความ “พบที่อยู่เดิม” การอัปเกรดจะหยุดและย้อนกลับทั้งชุด ต้องให้ผู้รับผิดชอบสำรองและจัดการข้อมูลที่อยู่เดิมตามข้อกำหนดของหน่วยงานก่อน ไม่แก้ SQL เพื่อลบการตรวจนี้โดยไม่ตรวจข้อมูล

ไฟล์ schema.sql ใช้เฉพาะโครงการใหม่ที่ตาราง public ของแอปยังว่าง ไม่ใช้เป็นคำสั่งอัปเกรดจากรุ่นเก่า ห้ามนำ migration รุ่น 1.7 หรือ 1.8 มารันย้อนหลังหลังใช้รุ่น 1.9

## 5. โครงสร้างข้อมูลหน่วยงานและฝ่าย

เลือกหน่วยงานหลักก่อน แล้วฟอร์มจะแสดงรายการฝ่าย/ส่วนราชการตามประเภทหน่วยงาน

| ประเภท | รายการตั้งต้น |
|---|---|
| ส่วนกลางสถาบัน | สำนักงานผู้อำนวยการสถาบัน |
| ส่วนกลางสถาบัน | สำนักพัฒนายุทธศาสตร์และความร่วมมืออาชีวศึกษา |
| ส่วนกลางสถาบัน | สำนักพัฒนากิจการนักศึกษาและกิจการพิเศษ |
| ส่วนกลางสถาบัน | ศูนย์วิจัยและพัฒนาการอาชีวศึกษา |
| ส่วนกลางสถาบัน | อาชีวศึกษาบัณฑิต |
| สถานศึกษา | ฝ่ายบริหารทรัพยากร |
| สถานศึกษา | ฝ่ายยุทธศาสตร์และแผนงาน |
| สถานศึกษา | ฝ่ายกิจการนักเรียน นักศึกษา |
| สถานศึกษา | ฝ่ายวิชาการ |

“งาน/แผนก/กลุ่มงาน” เป็นช่องเพิ่มเติม เช่น งานบริหารและพัฒนาทรัพยากรบุคคล หรือแผนกวิชาที่รับผิดชอบ ให้กรอกตามคำสั่งมอบหมายงานจริง ผู้เป็นผู้อำนวยการสามารถเว้นฝ่าย/ส่วนราชการว่างได้ ไม่มีช่องสถานะในฟอร์มกรอกบุคลากรใหม่

ชื่อฝ่ายเดิมที่ระบบรู้จัก เช่น แผนงานและความร่วมมือ ปรับเป็นฝ่ายยุทธศาสตร์และแผนงาน และพัฒนากิจการนักเรียนปรับเป็นฝ่ายกิจการนักเรียน นักศึกษา โดยเก็บประวัติก่อนและหลังเปลี่ยนชื่อไว้

หากมีส่วนราชการที่ตั้งเพิ่มตามคำสั่ง ให้ admin เปิดตั้งค่าระบบ → ตำแหน่ง สถานะ ฝ่าย และวิทยฐานะ → เพิ่มรายการ → เลือก “ส่วนราชการสถาบัน” หรือ “ฝ่ายสถานศึกษา (2569)” ให้ถูกประเภท แล้วเพิ่มชื่อรายการ เมื่อกลับไปกรอกบุคลากรจะพบรายการใหม่ อย่าเลือกหมวดฝ่ายวิทยาลัยแทนส่วนราชการสถาบัน

แหล่งโครงสร้างที่ใช้ตรวจสอบ: https://veis2.ac.th/government_structure/ และระเบียบบริหารสถานศึกษา 2569 ซึ่งหน่วยศึกษานิเทศก์ สอศ. เผยแพร่ประกอบที่ https://dles.vec.go.th/blog/47 รายละเอียดงานย่อยให้ใช้ตามคำสั่งของหน่วยงานที่มีผลใช้งาน

## 6. รูปแบบการกรอกที่เสนอและทำไว้ในระบบ

### 6.1 กรอกปกติ

1. เข้าสู่ระบบ → ข้อมูลบุคลากร → เพิ่มบุคลากร
2. ส่วนที่ 1 กรอกเลขที่ตำแหน่ง ชื่อ หน่วยงาน ตำแหน่ง ฝ่าย/ส่วนราชการ และงาน/แผนก/กลุ่มงาน
3. ส่วนที่ 2 กรอกวุฒิสูงสุดและสาขาวิชา ถ้ามีหลายสาขากด เพิ่มสาขาวิชา ทีละรายการ สูงสุด 20 สาขาของวุฒิสูงสุด
4. ส่วนที่ 3 กรอกอีเมล โทรศัพท์ และรูปโปรไฟล์ ไม่มีช่องที่อยู่
5. ส่วนที่ 4 เลือก เพิ่มข้อมูลใบรับรองวิชาชีพพร้อมบุคลากร หากมีใบรับรองที่ต้องเพิ่มทันที
6. กด ตรวจสอบก่อนบันทึก ตรวจชื่อบุคคล หน่วยงาน ฝ่าย และใบรับรอง แล้วทำเครื่องหมายยืนยันก่อนบันทึก
7. หากมีใบอื่น เปิดแฟ้มบุคลากร → เพิ่มใบรับรอง เพิ่มได้ทีละใบโดยไม่สร้างบุคลากรซ้ำ

### 6.2 ใบรับรองสมรรถนะทางวิชาชีพ

เลือกประเภท “ใบรับรองสมรรถนะทางวิชาชีพ” แล้วกรอก:

| ข้อมูล | วิธีกรอก |
|---|---|
| ชื่อใบรับรอง | ชื่อจริงตามหลักฐาน ต้องกรอก |
| หน่วยงานผู้ออก | ผู้ออกใบรับรองตามหลักฐาน ต้องกรอก |
| สาขาอาชีพ | เช่น เทคโนโลยีสารสนเทศ ให้ใช้ชื่อบนใบรับรอง |
| ระดับสมรรถนะ | เช่น ระดับ 4 กรอกตามหลักฐาน ไม่ใช่ระดับวุฒิการศึกษา |
| มาตรฐานอ้างอิง | ชื่อมาตรฐานตามเอกสาร ถ้าไม่มีเว้นว่าง |
| เลขที่ใบรับรอง | ตั้งเป็นข้อความเพื่อคงเลขศูนย์นำหน้า |
| วันที่ออก / หมดอายุ | กรอกตามเอกสาร ไม่มีวันหมดอายุให้เว้นว่าง |
| ไฟล์หลักฐาน | อัปโหลดผ่านแฟ้มเอกสารก่อน แล้วเลือกเชื่อมกับใบรับรองของบุคคลเดียวกัน |

กรณีอัปโหลดหลักฐาน เลือกประเภทเอกสารตามข้อกำหนดที่หน่วยงานใช้ เช่น วุฒิบัตรอบรม / เกียรติบัตร แล้วเชื่อมจากฟอร์มใบรับรอง การเพิ่มข้อมูลใบรับรองยังต้องอัปโหลดไฟล์หลักฐานแยกเพื่อให้ระบบตรวจเอกสารได้

ใบประกอบวิชาชีพครู ใบประกอบวิชาชีพผู้บริหาร และใบรับรองทักษะวิชาชีพเดิมยังแยกประเภทไว้ ระบบไม่เปลี่ยนใบเดิมให้เป็นสมรรถนะอัตโนมัติ

### 6.3 ค้นหาและติดตาม

หน้าภาพรวมมีแถบ “ใบรับรองสมรรถนะทางวิชาชีพ” กดเพื่อเปิดรายการประเภทนี้ และกดแถวส่วนกลางหรือวิทยาลัยเพื่อดูรายชื่อเฉพาะหน่วยงานได้ ระบบยังตรวจสิทธิ์ก่อนเปิดรายละเอียด

ในหน้าใบรับรอง ค้นได้จากชื่อบุคลากร เลขที่ตำแหน่ง ชื่อใบรับรอง ผู้ออก สาขาอาชีพ ระดับ และมาตรฐาน รายงานใบอนุญาตและใบรับรองส่งออกช่องสมรรถนะใหม่ได้ทั้ง CSV/Excel

## 7. ใช้ Excel นำเข้าครั้งแรกพร้อมใบรับรองหลายใบ

ใช้ Microsoft Excel เปิดแม่แบบ .xlsx ที่ดาวน์โหลดจากเว็บ แม่แบบมี 6 ชีตและใช้หัวตารางภาษาไทย:

| ชีต | ใช้ทำอะไร |
|---|---|
| บุคลากร | กรอกหนึ่งคนต่อหนึ่งแถว เริ่มแถว 2 |
| ใบรับรองวิชาชีพ | กรอกหนึ่งใบต่อหนึ่งแถว อ้างเลขที่ตำแหน่งของคนในชีตแรก |
| รายการอ้างอิง | เลือกชื่อหน่วยงาน ฝ่าย ประเภทใบรับรอง ตำแหน่ง และวิทยฐานะ |
| ตัวอย่าง | ข้อมูลสมมติสำหรับดูวิธีกรอก ระบบไม่นำเข้าชีตนี้ |
| ตัวอย่างใบรับรอง | ตัวอย่างหนึ่งคนมีหลายใบ ระบบไม่นำเข้าชีตนี้ |
| คำแนะนำ | วิธีกรอก ช่องที่ต้องกรอก ข้อจำกัดและรูปแบบวันที่ |

ลำดับชีตอาจต่างกัน ให้กรอกเฉพาะชีต บุคลากร และ ใบรับรองวิชาชีพ หัวตารางสองชีตนี้ตรงกับตัวนำเข้า และไฟล์ที่ดาวน์โหลดจากเว็บจะแสดงหน่วยงานตามสิทธิ์ปัจจุบัน

บุคลากรมี 13 คอลัมน์: เลขที่ตำแหน่ง, ชื่อ-นามสกุล, หน่วยงาน/สถานศึกษา, ตำแหน่ง, ฝ่าย/ส่วนราชการ, งาน/แผนก/กลุ่มงาน, วิทยฐานะ, วันเกิด, วันเริ่มงาน, อีเมล, โทรศัพท์, วุฒิการศึกษาสูงสุด, สาขาวิชา

ใบรับรองมี 10 คอลัมน์: เลขที่ตำแหน่ง, ประเภทใบรับรอง, ชื่อใบรับรองวิชาชีพ, หน่วยงานผู้ออก, เลขที่ใบรับรอง, วันที่ออก, วันหมดอายุ, สาขาอาชีพ, ระดับสมรรถนะ, มาตรฐานอ้างอิง

ตัวอย่างบุคลากรที่มีใบรับรอง 2 ใบ:

| ชีตบุคลากร | เลขที่ตำแหน่ง | ชื่อ |
|---|---|---|
| แถว 2 | 000123 | บุคลากร ตัวอย่าง |

| ชีตใบรับรองวิชาชีพ | เลขที่ตำแหน่ง | ชื่อใบรับรอง | ประเภท |
|---|---|---|---|
| แถว 2 | 000123 | ใบรับรองใบที่ 1 | ใบรับรองสมรรถนะทางวิชาชีพ |
| แถว 3 | 000123 | ใบรับรองใบที่ 2 | ใบรับรองสมรรถนะทางวิชาชีพ |

**หลายใบให้เพิ่มแถว ใช้เลขที่ตำแหน่งเดิม ไม่เพิ่มคอลัมน์ และไม่เพิ่มบุคลากรคนเดิมซ้ำในชีตบุคลากร** ข้อมูลทั้งสองชีตจะบันทึกพร้อมกัน ถ้ามีข้อผิดพลาดระบบไม่บันทึกชุดนั้น

1. คงชื่อชีตและหัวตารางภาษาไทย ช่องจำเป็นของบุคลากรคือ เลขที่ตำแหน่ง ชื่อ-นามสกุล และหน่วยงาน/สถานศึกษา ส่วนใบรับรองต้องกรอก เลขที่ตำแหน่ง ประเภทใบรับรอง ชื่อใบรับรองวิชาชีพ และหน่วยงานผู้ออก
2. เลือกชื่อหน่วยงานเต็มตามรายการ เพื่อหลีกเลี่ยงรหัสต่างจากโครงการเดิม
3. เลือกฝ่ายของวิทยาลัยหรือส่วนราชการสถาบันให้ตรงประเภท ระบบจะตรวจซ้ำก่อนนำเข้า
4. หลายสาขาวิชาในวุฒิสูงสุดให้คั่นด้วย ; เช่น การบริหารการศึกษา; เทคโนโลยีการศึกษา
5. วันที่ใช้ ค.ศ. YYYY-MM-DD หรือวันที่ Excel ไม่ใช้ปี พ.ศ. ใส่ในช่องวันที่ ค.ศ.
6. เลขที่ตำแหน่ง เลขที่ใบรับรอง และโทรศัพท์ใช้รูปแบบ Text เพื่อรักษาศูนย์นำหน้า
7. ไฟล์เก่ามี address หรือ ที่อยู่ ให้ลบคอลัมน์นี้ ไม่ใช่เพียงล้างค่า เพราะรุ่น 1.9 ไม่รับคอลัมน์ดังกล่าว
8. ไฟล์นี้ใช้เพิ่มรายชื่อใหม่ ไม่ใช้เขียนทับหรืออัปเดตรายชื่อเดิม ถ้าเลขที่ตำแหน่งซ้ำให้เปิดแก้ไขผ่านแฟ้มบุคลากร
9. จำกัด 500 คน / 5,000 ใบ / 100 ใบต่อคน / ไฟล์ไม่เกิน 5 MB ไม่ใส่สูตรในสองชีตนำเข้า
10. บันทึกเป็น .xlsx แล้วเปิดข้อมูลบุคลากร → อัปโหลด Excel → เลือกไฟล์ → ตรวจสอบ → ยืนยัน

## 8. แอดมินมอบหมายผู้รับผิดชอบส่วนกลางหรือวิทยาลัย

1. เพิ่มทะเบียนบุคลากรของผู้รับผิดชอบก่อน และเลือกหน่วยงานต้นสังกัดให้ถูกต้อง
2. เปิดจัดการบัญชี → สร้างบัญชี กำหนด Username และรหัสผ่านให้บุคลากรตามเดิม
3. เลือกกำหนดสิทธิ์ของบัญชีนั้น
4. เลือกหน่วยงานที่รับผิดชอบเป็นส่วนกลางสถาบัน หรือวิทยาลัยตามที่ได้รับมอบหมาย
5. เลือกขอบเขตทั้งหน่วยงานหรือเฉพาะรายชื่อ
6. เลือกสิทธิ์ตามงาน เช่น แก้ไขทะเบียน, แก้ไขวุฒิ, จัดการใบรับรอง, จัดการเอกสาร
7. ถ้าต้องนำเข้า Excel ต้องมีสิทธิ์ดูข้อมูล เพิ่มบุคลากร แก้ไขทะเบียน และนำเข้า พร้อมสิทธิ์วุฒิ/ใบรับรองเมื่อไฟล์มีข้อมูลส่วนนั้น และต้องรับผิดชอบทั้งหน่วยงาน
8. ระบุเหตุผล ตรวจรายการ แล้วบันทึก ให้ผู้รับผิดชอบออกจากระบบและเข้าสู่ระบบใหม่

บุคลากรทั่วไปแก้ไขช่องทางติดต่อและรูปตนเองได้ การแก้ทะเบียน วุฒิ หรือใบรับรองของคนอื่นต้องได้รับมอบหมาย สิทธิ์ส่วนกลางไม่เกิดขึ้นอัตโนมัติจากชื่อหรืออีเมล การลบทะเบียนยังให้ admin พิจารณาหรือดำเนินการ และมีประวัติ/กู้คืนตามระบบเดิม

## 9. เพิ่มหรือจัดการหน่วยงานในอนาคต

ใช้บัญชี admin เปิดตั้งค่าระบบ → หน่วยงานและสถานศึกษา → เพิ่มหน่วยงาน/สถานศึกษา กรอกชื่อ จังหวัด และประเภทหน่วยงานเป็น “สถานศึกษา” หรือ “ส่วนกลางสถาบัน”

แก้ไขชื่อ ปิดใช้งาน เปิดใช้งาน หรือลบได้ตามสิทธิ์พร้อมเหตุผล ระบบไม่ให้ลบถาวรเมื่อมีบุคลากรหรือสิทธิ์อ้างอิง ให้ปิดใช้งานแทน และไม่ให้เปลี่ยนประเภทหน่วยงานที่มีทะเบียนบุคลากรแล้ว เพื่อป้องกันฝ่ายไม่ตรงกับโครงสร้าง

กรณีเปลี่ยนฝ่าย/ส่วนราชการรายบุคคล ให้แก้ไขผ่านแฟ้มของบุคคลนั้น ตรวจค่าเดิม/ค่าใหม่ ระบุเหตุผล และยืนยัน ประวัติจะเก็บงาน/แผนก/กลุ่มงานใหม่ด้วย

## 10. อัปเดต Apps Script ของระบบเดิม

ฟิลด์ใหม่ส่งสำเนาไป Google Sheets ผ่านโค้ดอ่านคอลัมน์อัตโนมัติ ไม่ต้องเพิ่มคอลัมน์ในชีตด้วยมือ รุ่นนี้แก้ app_version ในไฟล์สำรองให้เป็น 1.9.0 ด้วย จึงควรอัปเดต Code.gs ให้ตรงกัน

1. เปิด https://script.google.com ผ่าน Chrome หรือ Edge แล้วเลือกโครงการ HR เดิม
2. เปิดไฟล์ apps-script/Code.gs รุ่น 1.9 ใน VS Code คัดลอกทั้งหมดไปแทนไฟล์ Code.gs ใน Apps Script แล้ว Save
3. ตรวจ Project Settings → Script properties ว่าค่าเดิม BRIDGE_SECRET, DRIVE_FOLDER_ID, SHEET_ID, SUPABASE_URL และ SUPABASE_SERVICE_ROLE_KEY ยังครบ ห้ามนำค่าลับเหล่านี้ใส่หน้าเว็บหรือ Excel
4. เลือก Deploy → Manage deployments → Edit ของ Web app เดิม
5. เลือก Version = New version → Deploy เพื่อคง URL /exec เดิม
6. หากสร้าง Deployment ใหม่จน URL เปลี่ยน ต้องแก้ GAS_URL ใน Supabase → Edge Functions → Secrets ให้ตรง URL /exec ใหม่
7. กลับเว็บจริง เข้าสู่ระบบ admin → ตั้งค่าระบบ → ส่งสำเนาไป Google Sheets แล้วเปิดชีตตรวจหน่วยงานและคอลัมน์สมรรถนะ
8. ทดสอบสำรองข้อมูล และตรวจไฟล์ JSON ว่า app_version เป็น 1.9.0

การแก้โค้ด Apps Script แล้วกด Save อย่างเดียวยังไม่เปลี่ยนโค้ดที่ Web app ใช้ ต้องเลือก New version และ Deploy

## 11. หากต้องติดตั้งใหม่ตั้งแต่ต้น

ส่วนนี้สำหรับโครงการใหม่ว่างเท่านั้น ไม่ต้องทำซ้ำในโครงการ HR ที่อัปเกรดแล้ว

1. สร้างโครงการ Supabase ใหม่ จด Project URL และ Publishable key ของโครงการนั้น
2. เปิด SQL Editor รัน supabase/schema.sql ฉบับเต็มหนึ่งครั้ง เพื่อสร้างตาราง กฎสิทธิ์ และข้อมูลหน่วยงานตั้งต้น
3. ใน Google Drive สร้างโฟลเดอร์ส่วนตัวสำหรับเอกสารและ Google Sheets สำหรับข้อมูลสำเนา ใช้บัญชีหน่วยงานที่รับผิดชอบ ไม่เปิดแชร์ไฟล์แบบ Anyone with the link
4. คัดลอก Folder ID จาก URL ของโฟลเดอร์ และ Sheet ID จาก URL ของ Google Sheets
5. สร้าง Apps Script วาง apps-script/Code.gs แล้วใส่ Script properties ตามตารางด้านล่าง
6. สร้าง BRIDGE_SECRET ด้วยคำสั่ง Node.js ใน Terminal เก็บค่าที่ได้ไว้เฉพาะผู้ติดตั้ง ใช้ค่าเดียวกันใน Apps Script และ Supabase Secrets
7. Deploy Apps Script เป็น Web app ให้รันด้วยสิทธิ์เจ้าของสคริปต์ และเปิดให้บริการเรียกโดยไม่ต้องล็อกอิน Google หากบัญชีองค์กรห้าม Anyone ต้องให้ผู้ดูแล Workspace จัดวิธีเข้าถึงที่บริการเรียกได้ โค้ดนี้ตรวจลายเซ็นคำขอทุกครั้ง
8. คัดลอก URL ที่ลงท้าย /exec เป็น GAS_URL
9. เปิดโฟลเดอร์หลักใน VS Code แล้วสร้าง .env จาก .env.example ใส่ GAS_URL, BRIDGE_SECRET และ ALLOWED_ORIGINS
10. สร้าง .env.bootstrap จาก scripts/bootstrap.env.example สำหรับสร้าง admin ในโครงการใหม่เท่านั้น
11. ตั้ง Secrets และ Deploy ฟังก์ชันตามตัวอย่าง แล้วสร้าง admin ครั้งแรก
12. ใส่ Project URL/Publishable key ของโครงการใหม่ลง dist/config.js และ deployment/config.production.js ก่อนเผยแพร่ GitHub Pages
13. สร้าง Repository ของหน่วยงาน ส่งโค้ดและเปิด GitHub Pages ผ่าน Actions ตามขั้นตอนที่ 3

```text
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

| ค่า | หาได้จากส่วนไหน | ใช้ที่ไหน |
|---|---|---|
| SUPABASE_URL | Dashboard → โครงการ → Project URL | Apps Script, .env.bootstrap และ dist/config.js |
| SUPABASE_SERVICE_ROLE_KEY | Dashboard → Settings → API Keys → Legacy service_role ของโครงการเดียวกัน | Apps Script และ .env.bootstrap เท่านั้น |
| Publishable key | Dashboard → Settings → API Keys → Publishable key | dist/config.js และ deployment/config.production.js |
| DRIVE_FOLDER_ID | ส่วนท้าย URL หลัง /folders/ ใน Google Drive | Apps Script Script properties |
| SHEET_ID | URL Google Sheets ระหว่าง /d/ และ /edit | Apps Script Script properties |
| BRIDGE_SECRET | ผลสุ่มจากคำสั่ง Node.js | Apps Script Script properties และ Supabase Secrets ใช้ค่าเดียวกัน |
| GAS_URL | Apps Script → Deploy → Web app URL ลงท้าย /exec | Supabase Secrets |
| ALLOWED_ORIGINS | ต้นทางเว็บไซต์จริง เช่น https://HRvec-adaman2.github.io | Supabase Secrets ไม่ใส่ path ของ Repository |

ตัวอย่าง .env สำหรับโครงการ HR ที่ใช้ GitHub Pages เดิม:

```text
GAS_URL=https://script.google.com/macros/s/รหัส_DEPLOYMENT_ของคุณ/exec
BRIDGE_SECRET=ค่าที่สุ่มและตรงกับใน_Apps_Script
ALLOWED_ORIGINS=https://hrvec-adaman2.github.io,https://hr-andaman2.muangyor.chatgpt.site
```

คำสั่ง Deploy ใช้ใน VS Code Terminal ที่โฟลเดอร์หลัก รันทีละบรรทัด เปลี่ยน PROJECT_REF เป็นรหัสโครงการใหม่ของคุณ ถ้าเป็น HR เดิมต้องเป็น oftlfxiywhtoftxluviv:

```text
npx.cmd supabase login
npx.cmd supabase link --project-ref PROJECT_REF
npx.cmd supabase secrets set --env-file .env --project-ref PROJECT_REF
npx.cmd supabase functions deploy hr-bridge --no-verify-jwt --use-api --project-ref PROJECT_REF
npx.cmd supabase functions deploy hr-accounts --no-verify-jwt --use-api --project-ref PROJECT_REF
npx.cmd supabase functions list --project-ref PROJECT_REF
```

--use-api ใช้บริการแพ็กเกจระหว่าง Deploy จึงไม่ต้องเปิด Docker สำหรับคำสั่ง Deploy นี้ ส่วน --no-verify-jwt ใช้คู่กับโค้ดในชุดนี้ ซึ่งตรวจผู้ใช้ เซสชัน และสิทธิ์ภายในฟังก์ชัน ต้องใช้โฟลเดอร์ functions ครบทั้งชุด

สร้าง admin เฉพาะโครงการใหม่ที่ยังไม่มี admin:

```text
node --env-file=.env.bootstrap scripts/bootstrap-admin.mjs
```

บัญชีเริ่มต้นคือ admin / 123456 ระบบบังคับเปลี่ยนก่อนเปิดข้อมูล สคริปต์ไม่สร้างซ้ำเมื่อมี admin อยู่แล้ว โครงการ HR เดิมให้ใช้รหัสปัจจุบันและไม่รันสคริปต์นี้ซ้ำ

Hosted Supabase จัดเตรียมตัวแปร SUPABASE_... ให้ Edge Functions เอง ไม่ส่ง .env.bootstrap เข้า Secrets และไม่อัปโหลดไฟล์ .env ทั้งสองไฟล์ขึ้น GitHub

## 12. ตรวจรับก่อนเปิดให้หน่วยงานกรอกข้อมูลจริง

ผลทดสอบโค้ดชุดส่งมอบ: 100 การทดสอบ Node.js; 76 ข้อทดสอบสิทธิ์รุ่น 1.8; 40 ข้อทดสอบฐานข้อมูลรุ่น 1.9; ทดสอบแม่แบบด้วยตัวอ่าน Excel ของเว็บ; และทดสอบฟอร์มส่วนกลาง/ใบรับรอง/หน้าตรวจสอบก่อนบันทึกในเบราว์เซอร์โหมดสาธิต รวมถึงตรวจ HTTP ระบบจริง 12 กรณีเกี่ยวกับ Origin และการปฏิเสธคำขอที่ไม่มีสิทธิ์

การตรวจระบบจริงในครั้งนี้ยืนยันฐานข้อมูลและสถานะ Edge Functions แล้ว ยังไม่ได้เข้าสู่ระบบด้วยรหัสผู้ใช้จริงหรืออัปโหลดไฟล์ไป Google Drive และยังไม่ได้ส่ง Commit เข้า Repository GitHub ของคุณ ต้องตรวจรับด้วยบัญชีหน่วยงานหลังอัปเดตหน้าเว็บและ Apps Script

Security Advisor ก่อนและหลังอัปเกรดมีคำเตือนเดิมเท่ากัน: ฟังก์ชัน SECURITY DEFINER ที่เปิดให้บัญชีผ่านการตรวจสิทธิ์เรียก 9 รายการ และ Leaked Password Protection ยังปิดอยู่ ผู้ติดตั้งควรตรวจการตั้งค่า Auth ก่อนเปิดใช้งานเต็มรูปแบบตามแผนบริการ โดยไม่ตัดการตรวจสิทธิ์ในฟังก์ชันเพื่อแก้คำเตือน
